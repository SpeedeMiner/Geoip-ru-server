## New independent finding — the exact ipverse archive can become unavailable

The [archive readback](v41-edge-ipverse-retrieval-20261114.json) shows that the moving branch URL still returned the exact compressed production input. Downloading the same embedded Git commit through its commit URL returned different compressed bytes, even though all 292,524 regular members matched by relative path and SHA-256. The audit cannot accept the second archive under the existing compressed-byte digest.

[Draft PR #32](https://github.com/SpeedeMiner/Geoip-ru-server/pull/32) proposes retaining the archive from the exact build in the candidate artifact and versioned snapshot. The rolling release stays small. The release commit carries a marker to locate its retained asset, and the audit rechecks the compressed byte length and SHA-256 against that same commit. A pre-retention release may still retrieve its original upstream URL only if those bytes match. This is a reproducibility change, not new coverage or reduced validation. All four PR #32 workflows passed. The [Actions candidate readback](v41-edge-pr32-build-artifact-20261114.json) includes the exact input bytes and a zero-delta publication preflight run without writes.

See the [execution journal](V41_EXECUTION_JOURNAL.md) for CI and final integrity readback. No production release was authorized by this audit.
