# v41 — Яндекс DNS через российские выходы VPNObratno

Для целевых A и AAAA не было запасного резолвера. DoT использовал порт 853, SNI `common.dot.dns.yandex.net` и стандартную проверку сертификата. Обнаружение VPN и проверка страны выхода выполнялись отдельно. Российские выходы и ASN указаны без IP выходов или данных VPN-профилей.

Контрольные хосты: `1906714720.rsc.cdn77.org` и `playercdn.cdnvideo.ru`. Итого 10/10 точечных IPv4 HTTPS-наблюдений дали CONNECTED / VERIFIED / 200 на четырёх различных IP. Только два из адресов, полученных по Яндекс DNS в этих запусках, были затем закреплены как дополнительные цели CDNvideo. Для `121.127.45.81` и `185.141.224.160` в этих запусках есть только DNS и проверка членства в DAT, не TCP/TLS. У CDNvideo HEAD проверяет корень хоста, а не работу плеера. Ни валидный TLS, ни HTTP 200 не подтверждают весь префикс. AAAA не означает проверку IPv6-транспорта.

Закреплённые DAT релиза `63b8abf` (SHA-256 `3dbbffd624d8bc4a50dac860135664578bd2e7742bdf66baa399beab3c65d3ec`) и кандидата (SHA-256 `02908f5e90cabb6cb29fdab664f9ae28b5777ad9f78bbda9fa18c824f07e070d`) перечитаны. В обоих три измеренных IPv4 CDNvideo входят в `RU:151.236.64.0/18`, а DNS-only `185.141.224.160` в `RU:185.141.224.0/22`. Оба адреса CDN77 вне RU и PRIVATE. Совпадение со снимком не меняет классификацию сети и не выводится из доступности.

## Шесть спорных /24

- 16 различных публичных имён проверены через Яндекс DNS в режиме DNS-only. Из них 8 (Link4, справочное имя 888 Ventures и шесть MX NetEase) повторились на AS12714 и AS6863 с одинаковыми ответами A и AAAA. Ни одного совпадения с шестью /24.
- Пассивная историческая зацепка `156.224.80.166` из [IPinfo](https://ipinfo.io/AS17561/156.224.80.0/24) и [архива DNS CuteStat](https://lomai.cfd.cutestat.com/) дала шесть публичных имён для проверки. Через Яндекс DNS с AS50512 пять вернули NXDOMAIN, `rndesk.com` вернул `104.21.85.82` и `172.67.203.219`; оба вне очереди. `www.link4bd.com` вернул `38.58.178.141` вне очереди, `www.888venturesllc.com` — NXDOMAIN.
- **0/6 подтверждённых актуальных пар** «сервисное имя → точный IPv4 внутри /24». Историческая привязка без актуального A не становится целью. TCP/TLS/HTTP к этим именам и адресам не выполнялись, подсети не сканировались. Отсутствие DNS-пары не доказывает блокировку или неработоспособность /24. [Ревью очереди](V41_EXACT_REACHABILITY_ORIGIN_REVIEW_20261117.md).
