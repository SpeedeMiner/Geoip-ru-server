# Паспорт сборки GeoIP DIRECT RU + BY + KZ v41

**SpeedeMiner/Geoip-ru-server · 17 ноября 2026 г.**

Паспорт описывает код `main` на коммите `af4e1f82adf769e3bd7d26ed30d4d3bc4012dd0d` и опубликованную сборку того же коммита из GitHub Actions [№44135258732][run]. Релиз содержит ровно два набора, `RU` и `PRIVATE`. В проверенном выпуске `RU` покрывает **53 418 134 IPv4-адреса** и содержит **15 115 IPv6 CIDR**. Публичные DAT и оба SRS совпали по SHA-256 с предыдущим снимком. Проверка выполнена без изменений в репозитории и без скачивания исходных IP-дампов или клиентских бинарников. Для чисел использованы небольшие отчёты, метрики CI и реестры.

## 1. Цель сборки и ключевая политика маршрутизации

**`RU` — список для выбора DIRECT, а не карта геолокации России.** Он объединяет IPv4 и IPv6 для ресурсов и origin ASN России, Беларуси и Казахстана, а также для подтверждённых корпоративных и операторских сетей и явно заданных сервисных маршрутов. `BY` и `KZ` не публикуются отдельно. `PRIVATE` обозначает локальные и специальные адреса, включая пространство шире RFC 1918. Сборщик не выдаёт категории `PROXY`, `BLOCK`, Telegram, CDN или GeoSite. Удаление из `RU` означает, что IP больше не получает DIRECT по этому набору. Дальнейший маршрут определяется клиентом.

| Слой | Что происходит при конфликте |
| --- | --- |
| `PRIVATE` | Абсолютный приоритет. Адрес остаётся в `PRIVATE` и не может остаться в `RU`, независимо от RIR, BGP, сервиса, ручного добавления или блок-фида. |
| Жёсткая IP-политика | Полный официальный Telegram-фид, закреплённые Telegram-маршруты, ограниченный актуальный Antifilter `subnet.lst` и вручную подтверждённые прямые IP/подсети. Они исключаются из `RU` даже при совпадении с `CORE_CORPORATE`, `SHARED_INFRA`, Hydra, сервисным или операторским allowlist. |
| Мягкая маска `resolver-only` | DNS-адреса из `ip.lst` и `ipresolve.lst` и не подтверждённая отдельно история v38. Вычитаются вне защищённых сетей. Не вырезают зарегистрированные ресурсы RU/BY/KZ, выбранные региональные origin-префиксы, точные префиксы обоих корпоративных классов, отдельные сервисные маски и проверенные операторские CIDR. |
| Точные конфликты допуска | Подтверждённое иностранное назначение вычитается из кандидата даже при региональной регистрации или origin. Сохраняется точное пересечение с независимым Hydra `DIRECT` / `WHITELIST` или с отдельно проверенным CDN-хостом. Оба независимых основания по-прежнему подчиняются `PRIVATE`, эффективным блокам и применимой маске IP-недоступности. |
| Проверенная IP-недоступность | Отдельная маска для IP-layer block или входящего IP-геоблока вне защищённого ядра. Ядро здесь — региональные ресурсы, выбранные origin, корпоративные префиксы и проверенные операторские CIDR. Не активируется только на основании DNS-ошибки, отказа для одного SNI, геолокационного ярлыка или отсутствия анонса. В текущей сборке реестр пуст. |

**Почему защищён `SHARED_INFRA`.** Один IP облака, хостинга, CDN или анти-DDoS может обслуживать несколько независимых арендаторов. Адрес, полученный резолвингом одного домена из блок-листа, не доказывает IP-блокировку всей площадки. Защита относится к конкретным origin-префиксам и только к мягкой маске, а не ко всем сетям провайдера. При нескольких origin ASN для точного CIDR (`MOAS`) наличие хотя бы одного `CORE_CORPORATE` относит CIDR к CORE, иначе применим `SHARED_INFRA`. REG.RU `AS197695` классифицирован как SHARED, но сам этот класс не даёт ASN-wide допуск сверх обычного регионального отбора. Географические и сервисные входы могут пересекаться, и отдельный источник не получает абсолютного приоритета только из-за своего названия.

**Доступность и зарубежные узлы.** RIR показывает регистрацию ресурса, ipverse — наблюдаемый origin, а явный whitelist — политику маршрутизации источника. Ни один из этих сигналов сам по себе не доказывает физическую локацию, работу каждого сервиса или доступность из домашней сети РФ. Иностранный IP может оставаться DIRECT по корпоративной принадлежности или явному сервисному основанию. Для измеренных CDN предусмотрен точечный допуск только одного публичного `/32` или `/128`, с раздельными доказательствами принадлежности и замера из RU ASN и сроком пересмотра. В выпуске таких записей **0**. Публичные сети Cloudflare, AWS, CloudFront и Google не добавляются и не вычитаются целиком по диагностическому реестру. Отдельный ручной VPN-пробник из PR №59 предназначен для ревью и не служит входом сборки или автоматическим решением о допуске.

**В клиенте** рекомендованный порядок — явные домены PROXY, затем проверенные домены DIRECT, затем IP-наборы `PRIVATE` и `RU` для DIRECT, затем PROXY по умолчанию. Это позволяет доменному правилу выигрывать у IP-правила на общем CDN. GeoIP не различает домены на одном IP. Источники — [политика v41][policy], [README][readme], [оверлей][overlay], [ручной VPN-пробник][probe].

## 2. Вклад внешних источников

**Как читать цифры.** «Входные CIDR» — записи категории либо уникальные префиксы конкретного входа, как указано в строке. «Адреса» — объединение диапазонов внутри источника. «Новые против v37» — то, что осталось у данного источника после политики и не покрывалось промежуточным v37. Это **не эксклюзивная доля** итогового `RU`. Один новый адрес может учитываться в нескольких строках. Отчёты о базовом v37 и финальном v41 нельзя подменять друг другом.

**Как проверяются поставщики.** Ветка разрешается один раз в точный коммит и Git tree, сверяются размер и Git blob SHA-1. Для релиза проверяются метаданные stable asset и размер, а SHA-256 сверяется с метаданными GitHub, если там есть дайджест. Для v2fly дополнительно проверяется его `geoip.dat.sha256sum`. SHA-256, URL, размер и статус каждого полученного файла записаны в provenance. Для текстовых CIDR применяются проверка семейства и каноничности, запрет default route и минимумы уникальных сетей **300/35** для агрегатов Kyoresuas IPv4/IPv6, **450** для W1ZARDZ и **40** для Escapingworm. Проверяются структура обязательного каталога сервисов и валидные CIDR в GeoIP. Для Hydra независимо проверяются наличие обеих категорий, хэш и полное допустимое покрытие после политики. HXEHEX может отсутствовать с явным диагностическим статусом. `v41-source-lock.json` — отдельный закреплённый набор, не список фактических версий этого rolling-прогона. ### Алгоритм очистки и защита от деградации

1. **Сборка в два этапа.** Go-база v37 считывает GeoIP protobuf, нормализует и проверяет префиксы, раскладывает пространства по trie, проводит операции объединения, пересечения и вычитания, затем вычитает PRIVATE и полный текущий approved block-union. Python-оверлей v41 добавляет региональные ресурсы, origin, сервисные списки, Hydra и кураторские префиксы. Он пересчитывает эффективную блок-маску, восстанавливает допустимое покрытие и повторно вычитает PRIVATE, effective block и точные admission-маски. Сортированные непересекающиеся интервалы IPv4 и IPv6 преобразуются обратно в минимальные CIDR. Это вычитание адресов, а не равенство строк CIDR: удаление дочернего `/25` из `/24` оставляет соседний `/25`.
2. **Независимая проверка результата.** Проверяются ровно два protobuf-тега, отсутствие пересечений RU/PRIVATE и RU/hard, origin- и Hydra-покрытие после исключений, все официальные Telegram CIDR, точные foreign-таблицы, шесть `/24` и привязка хэшей входов, отчётов и результата. В актуальном build job статусы финальной валидации и hard gate — **VALID/PASS**. В логе **417** Python-тестов общего набора, плюс отдельные тесты release gate.
3. **Абсолютные и относительные стоп-сигналы.** DAT ≤ **8 MiB**, не более **350 000** RU и **2 048** PRIVATE CIDR, RU ≤ **64 млн IPv4** и **2¹¹¹ IPv6** адресов. Самая широкая сеть RU — не шире `/8` IPv4 и `/24` IPv6. Добавления и удаления проверяются раздельно. Порог IPv4 — максимум из **4 096 адресов** и **0,5%** предыдущего покрытия, IPv6 — максимум из **2⁸⁰ адресов** и **1%**. Изменение PRIVATE или превышение порога требует проверки точного SHA-256 кандидата. Для 31 обязательного входа падение размера ниже **50%** прежнего — отдельный сигнал. Для принятых записей основных блок-фидов скачок по модулю более **50%** вызывает отдельную проверку, связанную с дайджестом статистики и входов.
4. **Поасеновые и региональные пороги.** Для приоритетных ASN и ресурсов RU/BY/KZ проверяется потеря **более 10%** адресного пространства прежнего входа по каждому семейству. Это сравнение входных инвентарей, не утверждение, что каждый такой адрес попал в DIRECT. В PR-сравнении это отчёт, в публикационном шаге проверка обязательна. В проверенном publish gate отдельные изменения IPv4/IPv6 равны **0**, PRIVATE не поменялся, обязательные источники не потребовали пересмотра.
5. **Контроль Xray и sing-box.** Для этого main-run оба SRS v1 скомпилированы sing-box **1.13.12**, декомпилированы и проверены на точное равенство адресного пространства категориям DAT. Матрица **8/8**: 4 IPv4, 4 IPv6, 6 DIRECT (Yandex DNS и авторитетные DNS `.by`, `.kz`) и 2 PROXY (Telegram). Сквозной тест процессов не запускается на push. Он прошёл в PR №59 на **тех же SHA-256 всех трёх клиентских файлов**: **18/18 на Xray 26.7.28 и 18/18 на sing-box 1.13.12**. Фикстуры покрывают приоритет доменов, резолвинг A/AAAA и IP-литералы в обоих семействах, а также RU, PRIVATE, внешние и Telegram-адреса. Это изолированные DNS/SOCKS тесты, не замеры реальной доступности.
