Адаптирован только этап [извлечения сертификата из reality-scanner-v2](https://github.com/SpeedeMiner/reality-scanner-v2/blob/f47839a52a485661a4b346c2c2dc07d01228a31b/main.go#L2945-L3019). [Код диагностики](https://github.com/SpeedeMiner/Geoip-ru-server/tree/8509bfc8e292e0a339b7e18fb473453703b44949/.github/reachability/cert-lead) использует uTLS v1.8.2, `HelloChrome_Auto` без SNI, сохраняет wildcard отдельно от точных SAN и не считает непроверенный сертификат доказательством сервиса. Go-тест на loopback подтвердил отсутствие SNI и сохранение wildcard. Прошли три Python-теста по новой ветке обработки и шесть существующих тестов транспорта Яндекс DNS.

Для найденных конкретных имён предусмотрена сверка A и AAAA только через Яндекс Basic UDP `77.88.8.8` после проверки выхода РФ. Повтор с валидируемым TLS/SNI и HTTP HEAD возможен только для имени, чей актуальный A содержит точный IP. В этой проверке сверка имён не выполнялась, потому что TLS не начался. Два контрольных хоста выполнялись отдельно через тот же выход, включая A/AAAA через Яндекс DNS.

[Обезличенный JSON обоих прогонов](v41-certificate-lead-156-224-80-166-20261117.json) содержит результаты и контрольные суммы ZIP из метаданных GitHub. IP выходов и VPN-профили не сохранены. Подсети не сканировались.

**Очередь остаётся 0/6.** Для следующего полезного замера нужен другой актуальный публично документированный IPv4 или подтверждённое оператором имя с адресом внутри одного из шести /24. Исторический адрес не повышен до сервисной цели. Правила DIRECT, PR №5, релиз и CDN не менялись.
