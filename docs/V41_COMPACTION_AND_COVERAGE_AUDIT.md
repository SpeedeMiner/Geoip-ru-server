# Аудит покрытия и сжатия GeoIP v41

**Безопасной дельты нет.** Ни одного кандидата в `SHARED_INFRA` для снятия мягких DNS-исключений. Все 15 самых фрагментированных блоков с однозначным origin разрезаны жёсткими проверенными IP-исключениями. Все 13 IPv6-анонсов RIPE RIS, которые закреплённый ipverse не покрывает целиком для того же origin ASN, уже полностью входят в опубликованный `RU`.

## 1. Кандидаты в SHARED_INFRA

Проверены **5 175** origin ASN с IPv4 вне 112 записей корпоративной политики. **5 173** выбраны по закреплённым RIR-записям RU/BY/KZ, **2** — только по метаданным `countryCode` ipverse. Для каждого RIR-origin всё наблюдавшееся IPv4-пространство уже входит в защищённый слой. Пересечение этого слоя с эффективной resolver-only маской пусто.

По коду корпоративные классы, выбранные региональные origins и региональные ресурсы RIR уже исключаются из мягкой маски. Перевод такого ASN в `SHARED_INFRA` не меняет его IPv4-покрытие и не снимает жёсткие исключения. Для незащищённого origin потеря от DNS подтверждалась лишь там, где эффективная resolver-only маска пересекалась с точным свидетельством `overlap_preblock_direct == addresses`. ## 2. IPv6 — закреплённый ipverse против RIPE RIS

Запрошено закрытое окно **2026-11-16 08:00 → 2026-11-17 08:00 UTC** через функции `get_ris`, `window_status` и `compare` из [`check_v41_bgp_observations.py`](../.github/scripts/check_v41_bgp_observations.py), с `min_peers_seeing=1`. Для всех **81 ASN** фактические границы ответа совпали с запрошенными. Это наблюдения за полное окно, а не требование непрерывной видимости анонса. В выборку вошли 26 записей основного приоритетного списка, 38 записей аудиторской watchlist и 75 записей корпоративного реестра (банки, платёжная инфраструктура, связь, хостинг и облака). ## 3. Топ-15 почти полных агрегатов IPv4

Пороги — выровненный `/20`–`/23`, не менее 6 CIDR после `collapse_addresses` и не менее 75% адресов в `RU`. Из **192** блоков, прошедших пороги, **48** удалось отнести к одному региональному или корпоративному origin. Проверены наиболее специфичные маршруты закреплённого ipverse, в том числе иностранные origins в этих блоках. Равные по специфичности маршруты разных ASN, смена origin внутри блока или отсутствие атрибуции для уже покрытого пространства исключают блок из этого топа.

У всех **48** прошедших блоков дырки совпали с жёсткими IP-исключениями из [`v41-reviewed-rkn-ip-records.tsv`](../.github/data/v41-reviewed-rkn-ip-records.tsv). Ни одного доказанного soft carve-out, необъяснённого разрыва или отсутствующего промежуточного `/24`, требующего нового допуска. У всех 15 строк ниже есть покрывающий маршрут того же ASN в ipverse. Отсутствие отдельного `/24` не объясняет вычитание адресов из такого маршрута.

Ранг определяется числом CIDR, затем адресом блока и длиной префикса.
Вложенные блоки показаны намеренно, их потери не складываются.
Например, в `188.124.232.0/21` отсутствует 61 IPv4, все в
`188.124.237.0/24`. Дочерний `188.124.236.0/22` показывает те же
61 адрес, а не ещё 61. Для `93.84.112.0/20` и трёх его потомков
причина одна и та же — `93.84.112.94/32` и `93.84.112.98/32`.
Диагностический JSON выводит точное множество дырок для каждой строки.
`PRIVATE`, Telegram, `subnet.lst` и reviewed RKN классифицируются отдельно.
Первые три жёстких слоя не объясняют дырки в приведённом топе.

## Итоговый эффект и проверка

- **IPv4 RU:** 17 689 CIDR, 53 418 134 адреса. Подтверждённая дельта —
  **0 CIDR и 0 IPv4**. В `RU` также 15 115 IPv6 CIDR, всего 32 804 CIDR.
  Рассмотренные IPv6-анонсы не увеличивают покрытие.
- **`geoip_RU.dat`: 512 511 байт, экономия 0 байт (0%).**
  Каноническое кодирование из свёрнутых интервалов воспроизвело SHA-256
  `02908f5e90cabb6cb29fdab664f9ae28b5777ad9f78bbda9fa18c824f07e070d`.
- **`geoip_RU.srs`: 128 234 байт, экономия 0 байт (0%).**
  Оба SRS скомпилированы и обратно декодированы штатным скриптом и
  закреплённым sing-box 1.13.12. Байты `RU` и `PRIVATE` совпали со
  снимком. Размер SRS не оценивался пропорционально числу CIDR.
- Python: пройден полный набор из 422 тестов. Go: пройден
  `go test ./...` для `geoip-v37-builder` с Go 1.26.10.
- PR содержит только отчёт, read-only диагностический скрипт и его
  тесты. Код не изменяет маршруты, реестры, настройки и workflow,
  не публикует результаты и не запускает VPN или сетевое сканирование.

### Воспроизведение

Восстановить закреплённые входы по
[инструкции offline replay](V41_OFFLINE_SNAPSHOT_REPLAY.md). Из
`878b1a97fdd3e05033b7fa3a3e6ab79c56bfe0f2` извлечь
`geoip_RU.dat`, `geoip_RU_v41_manifest.json`,
`geoip_RU_v41_rir_ru_and_company_origin_prefixes.txt`,
`geoip_RU_blocked_ip_exact_and_legacy_hard.txt`,
`geoip_RU_v41_blocked_ip_exclusions.txt` и
`geoip_RU_v41_blocked_provenance.tsv` в `$SNAPSHOT`. SHA-256
эффективной маски и blocked-provenance соответственно
`85c47f365fd87fed341d60e9d494a5a5e323394ff6b3e82748f5151b55aabbc9` и
`948d5d13fdd2b20adac705e19956cbc2a56e1ccd45ea0bc1a0ea5e943345e8ba`.

```bash
python3 .github/scripts/audit_v41_direct_provenance.py \
  --catalog .github/data/v41-audit-global-networks.json \
  --collect-snapshot "$PROVIDERS"
python3 .github/scripts/audit_v41_compaction.py \
  --snapshot "$SNAPSHOT" --restored "$RESTORED" \
  --providers "$PROVIDERS" > compaction.json
python3 -m unittest discover -s .github/scripts -p 'test_*.py'
```
