# GeoIP v41: состояние и незавершённые задачи

Срез на 16 ноября 2026 года. Цель — довести до проверяемого релиза модель **Direct by Reachability**: региональные сети RU/BY/KZ и подтверждённые локальные ресурсы, а также другие узлы, доступные напрямую из РФ, направляются по принятой политике. Зарубежная регистрация сама по себе не доказывает недоступность; доступность нельзя вывести только из BGP, DNS или RDAP. Полный утверждённый план и хронология — в [журнале](V41_EXECUTION_JOURNAL.md).

## Состояние передачи

- Основная ветка содержит журнал, но **не содержит** рабочие изменения реализации. Они подготовлены в отдельной ветке передачи; это кандидат, а не выпущенная версия.
- Локальная разработка начата от `c0d2a01ba1fb5f5c0e48965d614945348083a900`. К моменту передачи в main поверх этой базы менялся только журнал. Обновление main следует проверить повторно перед объединением.
- Прошли 103 выбранных Python-теста, ранее — Go unit tests сборщика; синтаксис обновлённого shell-загрузчика проверен. Проверки выполнялись локально на Windows; полный Linux CI и сборка с реальными источниками не завершились.
- Финальный DAT, крупные IP-дампы и файлы релизов в ходе работы не читались. Фактический diff кандидата и опубликованной базы, а также сетевая доступность из РФ не определены.
- Корпоративный реестр и политика содержат по 112 согласованных ASN; 26 ASN входят в контроль потерь, 13 — в диагностическую BGP-сверку. В справочном перечне 11 доменов. Эти числа не означают полноту покрытия.

## Незавершённые задачи

### 1. Защитить и проверить сборку — высокий приоритет

- [ ] Разобрать изменения кандидата целиком, включая untracked-файлы, затем проверить их на актуальной версии main. Не считать отметки в журнале подтверждением публикации кода.
- [ ] Запустить полный набор тестов и сборку в Linux CI на отдельной ветке/PR. Проанализировать ошибки, предупреждения и результаты обязательных проверок, повторить после исправлений. Не запускать рабочий процесс публикации из main до проверки кандидата.
- [ ] В [черновике PR №56](https://github.com/SpeedeMiner/Geoip-ru-server/pull/56) сборка v41 остановилась при проверке количества записей LACNIC; выяснить расхождение с форматом и устранить его без неконтролируемого ослабления fail-closed. Добавлена диагностика агрегированных счётчиков, требуется повторный CI.
- [ ] Повторный CI дал одинаковые итоги на трёх зеркалах: заявлено 50216 записей, фактически 48502; расхождение только по ASN (16142 против 14428 строк). Следующий CI показал сумму размеров ASN-диапазонов 14428, так что гипотеза об ином подсчёте диапазонов не подтвердилась. Найти объяснение или независимый проверенный источник; IPv4/IPv6 счётчики совпали. Проверку полноты не ослабляли.
- [ ] Проверить результат [аудита префиксов v37](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43916821833), который при последней проверке ожидал внешние RDAP/RPKI ответы. Отдельная сборка v39 и синтаксическая проверка v41 прошли; основной CI v41 завершился ошибкой LACNIC.
- [ ] Выполнить реализованное сравнение кандидата с закреплённым опубликованным релизом: отдельные добавления и удаления IPv4/IPv6, число CIDR, PRIVATE и разрез по источникам. Оценить побочные изменения от новой политики, в том числе отказа считать зарубежную регистрацию самостоятельным основанием для исключения. Зафиксировать SHA кандидата и результаты ревью.
- [ ] Проверить DAT и декомпилированные SRS в CI: категории, эквивалентность покрытия, приоритет PRIVATE/жёстких исключений/Telegram и прохождение независимых проверок. Дополнить матрицу подтверждёнными примерами BY и KZ, IPv4/IPv6 и PROXY; текущие два адреса Яндекс DNS не доказывают доступность из РФ.
- [ ] Протестировать пороги общего изменения и потерь по странам и критичным ASN, включая ручное подтверждение точного SHA кандидата. Контроль 10% относится к входным наборам до применения политики и не равен потере итогового покрытия DIRECT; для семейства без исходной базы выводится `no-baseline`.
- [ ] Проверить защиту каждого обязательного источника на уровне формата, структуры, ответов-ошибок и количества записей; дополнить реалистичными нижними порогами и тестами отказов. Уже есть проверка HTML/XML, полноты и свежести пяти RIR и эвристика падения размера 31 источника более чем на 50%, но они не покрывают все виды повреждения.
- [ ] Проверить в Linux CI совместимость усиленного разбора Kyoresuas `services.json` с полным реальным источником. Некорректные категории и записи теперь отклоняются; локально проверены только синтетические случаи и небольшой фрагмент формата.
- [x] Ранняя проверка этого каталога добавлена после загрузки закреплённого источника, до RIR; для запуска с реальными данными нужен повторный CI.
- [ ] Повторный CI актуального коммита не запустился автоматически. Проверка разрешений отклонила временное закрытие PR для повторного открытия и запуска CI, поскольку это меняет публичное состояние проекта; PR остаётся открытым. Нужен разрешённый пользователем способ запуска проверки.
- [ ] Проверить строгий разбор таблицы количества источников на настоящем отчёте сборщика в Linux CI. Синтетические тесты отклоняют повторы, повреждённые строки и неверные итоги.

### 2. Подтвердить маршрутизацию и источники

- [ ] Организовать воспроизводимые измерения доступности из сетей РФ и оценить результаты для IP-блокировок и входящих геоблокировок. Различать IP-блок, SNI/DNS и прикладной отказ; фиксировать источник, дату, метод и срок повторной проверки.
- [ ] Пополнять `v41-reviewed-unreachable.tsv` только подтверждёнными IP-уровневыми случаями; сейчас реестр пуст. Проверить сохранение регионального и корпоративного ядра и приоритет действующих жёстких исключений. Не делать вывод о доступности или недоступности по одной стране регистрации.
- [ ] Расширить аудит корпоративных и инфраструктурных ASN RU/BY/KZ, включая иностранные аффилированные origin ASN; отдельно проверять принадлежность, роль инфраструктуры и IPv4/IPv6. Не добавлять транзитные и глобальные ASN только из-за соседства или DNS. Для общего хостинга сохранять осторожную классификацию.
- [ ] Расширить и проверить BGP-диагностику на реальных CI-входах. Сопоставлять адресное пространство по семействам, учитывать разные окна ipverse и RIPE RIS, неполные окна и ошибки источника. Расхождения направлять на ручное ревью, а не добавлять маршруты автоматически.
- [ ] Рассмотреть расхождение для Kaspi AS35673: RIPE RIS видел `82.115.37.0/24`, которого не было в проверенном индивидуальном снимке ipverse. [RIPE RDAP](https://rdap.db.ripe.net/ip/82.115.37.0/24) связывает родительский диапазон с банком. Установить покрытие кандидата через подготовленный CI-отчёт и проверить источники; нельзя утверждать, что диапазон отсутствует в релизе или доступен из РФ.
- [ ] Уточнить актуального пользователя AS43934: запись RIPE содержит историческое название КЦМР, который по [официальному сообщению](https://npck.kz/o-sozdanii-naczionalnoj-platezhnoj-korporaczii-naczionalnogo-banka-respubliki-kazahstan/) реорганизован в 2023 году. Использование этого ASN правопреемником не установлено.
- [ ] Расширить реестр критичных сервисов и проверить источники официальных перечней Минцифры; существующие 11 записей подтверждают домены, а не членство в перечнях, выделенные IP или доступность из РФ. Для сервисов на общем CDN документировать необходимость доменного правила; не выводить широкое IP-исключение из DNS.

### 3. Прозрачность и клиентские конфигурации

- [ ] Завершить сквозное отслеживание происхождения префиксов до финального схлопывания, включая regional RIR, corporate, shared infrastructure, Hydra и overrides. Объяснять пересечения источников и не суммировать их как независимое пространство.
- [x] Исправить завышение метрики числа сетей из Kyoresuas JSON после добавления агрегатных входов; проверено синтетическим тестом без изменения итогового объединения.
- [ ] Проверить метрики CIDR и размера DAT/SRS на реальной сборке. Числа сетей и адресов доступны раздельно по семействам, но общие байты смешанного файла нельзя честно разнести между IPv4 и IPv6 без отдельной методики.
- [ ] Проверить примеры порядка правил Xray и sing-box на конкретных клиентских конфигурациях, включая конфликты доменных правил, PRIVATE, DIRECT и PROXY. Описанные в локальном README примеры пока не подтверждены практической проверкой.
- [ ] Проверить предупреждения о статических overrides без актуального BGP-наблюдения и с истекшим сроком ревью; они предназначены для ручной проверки и не должны автоматически менять маршруты.

### 4. Завершение и публикация
