# GeoIP v41: состояние и незавершённые задачи

Срез на 16 ноября 2026 года. Цель — довести до проверяемого релиза модель **Direct by Reachability**: региональные сети RU/BY/KZ и подтверждённые локальные ресурсы, а также другие узлы, доступные напрямую из РФ, направляются по принятой политике. Зарубежная регистрация сама по себе не доказывает недоступность; доступность нельзя вывести только из BGP, DNS или RDAP. Полный утверждённый план и хронология — в [журнале](V41_EXECUTION_JOURNAL.md).

## Состояние передачи

- Основная ветка содержит журнал, но **не содержит** рабочие изменения реализации. Они подготовлены в отдельной ветке передачи; это кандидат, а не выпущенная версия.
- Локальная разработка начата от `c0d2a01ba1fb5f5c0e48965d614945348083a900`. К моменту передачи в main поверх этой базы менялся только журнал. Обновление main следует проверить повторно перед объединением.
- [Последний проверенный Linux CI v41 №349](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43924047898) на исходниках `10833068a021e78602ce3927608ac34c4ceef2f8`: 310 Python-тестов, Go unit tests и сборка прошли. Публикация пропущена. Диагностика BGP дала 9 тайм-аутов и 4 неполных окна без дельты по полученным данным. Подробности и SHA-256 отчётов — в журнале этой ветки.
- Финальный DAT, крупные IP-дампы и файлы релизов вручную не читались; автоматический CI сравнил кандидата с release `63b8abf0ba6c2264724a58ec9a2fb7035c5130a6`. Сетевая доступность из РФ не определена.
- Корпоративный реестр и политика содержат по 112 согласованных ASN; 26 ASN входят в контроль потерь, 13 — в диагностическую BGP-сверку. В справочном перечне 11 доменов. Эти числа не означают полноту покрытия.

## Незавершённые задачи

### 1. Защитить и проверить сборку — высокий приоритет

- [ ] Разобрать изменения кандидата целиком, включая untracked-файлы, затем проверить их на актуальной версии main. Не считать отметки в журнале подтверждением публикации кода.
- [x] Полный набор тестов и сборка Linux CI на черновике PR №56 прошли. Предпубликационный сценарий из задания `publish` не исполнялся. Повторить CI после изменений кода и провести проверку релиза без записи в публичные refs.
- [x] В [черновике PR №56](https://github.com/SpeedeMiner/Geoip-ru-server/pull/56) стандартный LACNIC-файл не прошёл проверки, но CI успешно принял официальный расширенный файл после тех же строгих проверок. Обычный файл остаётся отклонённым; fail-closed не ослаблялся.
- [ ] Повторный CI дал одинаковые итоги на трёх зеркалах: заявлено 50216 записей, фактически 48502; расхождение только по ASN (16142 против 14428 строк). Следующий CI показал сумму размеров ASN-диапазонов 14428, так что гипотеза об ином подсчёте диапазонов не подтвердилась. Найти объяснение или независимый проверенный источник; IPv4/IPv6 счётчики совпали. Проверку полноты не ослабляли.
- [x] Исходный [аудит v37](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43916821833) отменён на RDAP/RPKI. [Повтор](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43924047858) прошёл, включая сбор RDAP/RPKI и выгрузку отчёта.
- [x] CI подтвердил агрегированную дельту против закреплённого release `63b8abf`: добавлено 41 629 IPv4 и 4 835 703 278 458 516 698 824 704 IPv6 адреса, удалений нет, PRIVATE не изменился. SHA-256 DAT `2b52d36c63235031d62410a53ea2ec89f925a33b543f217d44691621ec753af4`.
- [ ] Выгрузить точные добавленные CIDR и проверить их происхождение и побочные изменения политики. Сопоставить реализацию с [PR №46](https://github.com/SpeedeMiner/Geoip-ru-server/pull/46), отдельно сверить семь спорных /24 из [PR №53](https://github.com/SpeedeMiner/Geoip-ru-server/pull/53). Суммарная дельта и размеры входов не заменяют это ревью.
- [x] DAT и оба декомпилированных SRS прошли автоматическую проверку эквивалентности покрытия. CI также подтвердил независимые проверки PRIVATE, жёсткой политики и Telegram.
- [ ] Дополнить матрицу примерами BY и KZ, IPv4/IPv6 и подтверждёнными PROXY. Сейчас два DIRECT-примера Яндекс DNS, которые не доказывают доступность из РФ.
- [ ] Протестировать пороги общего изменения и потерь по странам и критичным ASN, включая ручное подтверждение точного SHA кандидата. Контроль 10% относится к входным наборам до применения политики и не равен потере итогового покрытия DIRECT; для семейства без исходной базы выводится `no-baseline`.
- [ ] Проверить защиту каждого обязательного источника на уровне формата, структуры, ответов-ошибок и количества записей; дополнить реалистичными нижними порогами и тестами отказов. Уже есть проверка HTML/XML, полноты и свежести пяти RIR и эвристика падения размера 31 источника более чем на 50%, но они не покрывают все виды повреждения.
- [x] Совместимость усиленного разбора Kyoresuas `services.json` с полным закреплённым источником проверена в Linux CI. Ранний этап принял 90 сервисов и 986 уникальных префиксов в [первом запуске](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43921730034); [финальный CI](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43924047898) дошёл до сборки и проверки кандидата.
- [x] Официальный расширенный файл LACNIC прошёл те же проверки полноты и свежести в CI; принято 97706 записей. Дальнейшая проверка свежих снимков остаётся частью обычных запусков.
- [x] Строгий разбор применён к фактической таблице счётчиков при проверке базового DAT в Linux CI. Отрицательные сценарии остаются покрыты синтетическими тестами.

### 2. Подтвердить маршрутизацию и источники

- [ ] Организовать воспроизводимые измерения из подтверждённой домашней сети РФ по точному списку спорных адресов, с IPv4/IPv6 отдельно. Различать IP-блок, SNI/DNS и прикладной отказ; фиксировать источник, дату, метод и срок повторной проверки. Старый [VPNObratno-пилот](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43093976146) подтвердил один RU-выход AS6856, но только 28/30 целей и без подтверждения домашнего типа сети. Он не доказывает доступность новых CIDR.
- [ ] Пополнять `v41-reviewed-unreachable.tsv` только подтверждёнными IP-уровневыми случаями; сейчас реестр пуст. Проверить сохранение регионального и корпоративного ядра и приоритет действующих жёстких исключений. Не делать вывод о доступности или недоступности по одной стране регистрации.
- [ ] Расширить аудит корпоративных и инфраструктурных ASN RU/BY/KZ, включая иностранные аффилированные origin ASN; отдельно проверять принадлежность, роль инфраструктуры и IPv4/IPv6. Не добавлять транзитные и глобальные ASN только из-за соседства или DNS. Для общего хостинга сохранять осторожную классификацию.
- [ ] Расширить и проверить BGP-диагностику на реальных CI-входах. Сопоставлять адресное пространство по семействам, учитывать разные окна ipverse и RIPE RIS, неполные окна и ошибки источника. Расхождения направлять на ручное ревью, а не добавлять маршруты автоматически.
- [x] Рассмотрено расхождение для Kaspi AS35673: [CI-отчёт](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43922390417) показал покрытие `82.115.37.0/24` целиком в DIRECT кандидата. Это не утверждение о покрытии прежнего релиза или доступности из РФ.
- [x] По [повторному BGP-артефакту](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43924047898/artifacts/14256820357) установлены причины отсутствия данных: 9 `TimeoutError`, остальные 4 ASN вернули `partial-window` и нулевую дельту по полученным данным.
- [ ] Добиться воспроизводимости RIPE RIS с ограниченным бюджетом запросов: проверить повтор на закреплённом окне и наблюдать частоту тайм-аутов. Не превращать неполные окна и сетевые ошибки в исчезновение маршрутов.
- [ ] Уточнить актуального пользователя AS43934: запись RIPE содержит историческое название КЦМР, который по [официальному сообщению](https://npck.kz/o-sozdanii-naczionalnoj-platezhnoj-korporaczii-naczionalnogo-banka-respubliki-kazahstan/) реорганизован в 2023 году. Использование этого ASN правопреемником не установлено.
- [ ] Расширить реестр критичных сервисов и проверить источники официальных перечней Минцифры; существующие 11 записей подтверждают домены, а не членство в перечнях, выделенные IP или доступность из РФ. Для сервисов на общем CDN документировать необходимость доменного правила; не выводить широкое IP-исключение из DNS.

### 3. Прозрачность и клиентские конфигурации

- [ ] Завершить сквозное отслеживание происхождения префиксов до финального схлопывания, включая regional RIR, corporate, shared infrastructure, Hydra и overrides. Объяснять пересечения источников и не суммировать их как независимое пространство.
- [x] Исправить завышение метрики числа сетей из Kyoresuas JSON после добавления агрегатных входов; проверено синтетическим тестом без изменения итогового объединения.
- [x] [Метрики реальной сборки](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/43924047898/artifacts/14256505565) сверены: DAT 512 787 Б, RU SRS 128 294 Б, PRIVATE SRS 228 Б. Число CIDR считается по семействам; общие байты смешанного файла не делятся между IPv4 и IPv6.
- [ ] Проверить примеры порядка правил Xray и sing-box на конкретных клиентских конфигурациях, включая конфликты доменных правил, PRIVATE, DIRECT и PROXY. Описанные в локальном README примеры пока не подтверждены практической проверкой.
- [ ] Проверить предупреждения о статических overrides без актуального BGP-наблюдения и с истекшим сроком ревью; они предназначены для ручной проверки и не должны автоматически менять маршруты.

### 4. Завершение и публикация

- [ ] После успешного независимого ревью и CI подготовить решение о включении изменений в основную ветку. Перед публикацией сверить фактический diff, источники, результаты проверок и точный SHA кандидата; зафиксировать оставшиеся ограничения и план отката.
- [ ] Проверить, какие именно артефакты и правила реально применяются клиентами, и провести ограниченную проверку совместимости. Не обозначать задачу как завершённую только по результатам синтетических тестов или публикации этого документа.
