# v41 — сквозная проверка DNS и выбора маршрута

Проверка 17 ноября 2026 на [GitHub Actions](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/44046623361) на коде `e115cf8`. Запуски Xray **26.7.28** и sing-box **1.13.12** использовали опубликованные DAT и оба SRS из неизменяемого `63b8abf`. Права root использовались только для создания отдельного Linux network namespace и поднятия loopback. Оба клиента работали от непривилегированного пользователя. DNS и SOCKS работали на `127.0.0.1`, фиктивные SOCKS-приёмники не соединялись с проверяемыми IP или доменами.

| Случай | Xray | sing-box |
|---|---|---|
| Домен есть и в PROXY, и в WHITELIST | PROXY, DNS не было | PROXY, DNS не было |
| WHITELIST-домен с потенциальным внешним A | DIRECT, DNS не было | DIRECT, DNS не было |
| Новый домен с синтетическим ответом RU или PRIVATE, IPv4/IPv6 | DIRECT после DNS, SOCKS получил доменное имя | DIRECT после DNS, SOCKS получил IP |
| Новый домен с ответом для внешнего адреса или Telegram, IPv4/IPv6 | PROXY после DNS, SOCKS получил доменное имя | PROXY после DNS, SOCKS получил IP |
| Точный IP RU/PRIVATE, внешний IP и Telegram, оба семейства | DIRECT для RU/PRIVATE, иначе PROXY, без DNS | То же |

Всего 18/18 у каждого клиента. В восьми сценариях с DNS оба клиента запрашивали A и AAAA у локальной фикстуры. IP-литералы и домены, пойманные первыми правилами, её не запрашивали. Для Xray тестировался `IPOnDemand`, для sing-box — `action: resolve` после доменных правил и перед IP-правилами. Разница в том, что SOCKS получает после разрешения, относится к этим конфигурациям. Это не вывод о поведении других outbounds, маршрутизации пользовательского DNS или получателях DNS-трафика дома.

[Архив отчёта](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/44046623361/artifacts/14311991564) сверен с GitHub SHA-256 `ad65e9df93f2713e6cbb80a4f311408e9a9e025feaa9538a548ada95be94a639` и CRC. SHA-256 JSON `3af2af55f1219db5f0d2b4ee1f052c62cd8e184e07140071962da5cf69ae6365`.

На актуальном, ещё не опубликованном DAT `02908f5e…` Xray дополнительно прошёл те же 18 сценариев локально. Оба SRS кандидата отдельно прочитаны `sing-box rule-set match`: все восемь точных IP-контролей согласуются с ожидаемыми RU/PRIVATE и внешними случаями. Полноценный процесс sing-box в контейнере рабочей среды не запускается из-за netlink, поэтому его сквозной DNS-прогон на runner относится к опубликованному снимку. Это ограничение не скрыто и не заменяет проверку кандидата на фактической пользовательской конфигурации.

Ни одна из проверок не является VPN-замером, проверкой домашней доступности из РФ или изменением клиентских конфигураций в релизе.
