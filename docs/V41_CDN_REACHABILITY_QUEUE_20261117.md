## Как закрыть строку

1. На подтверждённом домашнем RU-выходе получить A и AAAA фактического имени и проверить их точную привязку к услуге CDN. Не переносить IP из DNS-снимка другой сети без сверки: CDN может выбрать другой edge.
2. Для каждого семейства отдельно выполнить небольшую проверку публичного ресурса с исходным именем для Host и TLS SNI и записать фактический IP подключения, ASN выхода, время, TLS и ответ сервиса. Без AAAA или IPv6-выхода IPv6 остаётся непроверенным.
3. Успешный операторский ответ, PTR, DNS, TCP без приложения, единичный 403/503, редирект или тайм-аут не являются сами по себе основанием для добавления либо удаления адреса. Если важен один сайт на общей CDN, предпочесть правило домена.
4. После ручной проверки сохранить только подтверждённый одиночный IP с источником провайдера и датированным доказательством из РФ. Приватные данные домашнего выхода не публиковать. Политика PRIVATE и существующие жёсткие блокировки сохраняют приоритет.

## История предыдущего кандидата без WHITELIST

Эта часть относится к предыдущей версии. В текущем черновике явный Hydra WHITELIST снова участвует в DIRECT. Его наличие само по себе не превращает адрес в подтверждённый CDN и не обосновывает импорт ASN.

На закреплённом снимке 767 адресов из десяти точных CIDR потеряли единственное основание в Hydra WHITELIST. Для групп `103.111.114.0/24`, `185.141.216.0/24` (в дельте только 255 адресов) и `185.177.73.0/24` RIPEstat показал соответственно [AS8849](https://stat.ripe.net/data/prefix-overview/data.json?resource=103.111.114.0%2F24) через covering /22, [AS26832](https://stat.ripe.net/data/prefix-overview/data.json?resource=185.141.216.0%2F24) и [AS202448](https://stat.ripe.net/data/prefix-overview/data.json?resource=185.177.73.0%2F24). Наличие тестовой CDNvideo-точки в другом префиксе AS8849 не обосновывает возврат `103.111.114.0/24`. Это изменение допуска, не заключение об IP-блокировке.

## Ранее существующее пересечение с Cloudflare

Сверены [официальные сети Cloudflare](https://www.cloudflare.com/ips/) по IPv4 (15 CIDR, SHA-256 `f02c6d83bc01ab0ae8577160e036d700c7455359bce054df884e5d7d9e4e9e7b`) и IPv6 (7 CIDR, SHA-256 `9e9d39e3e83bad00c4decafd53c63fa62029f3d95db68de937d2be28234ca0a9`). В опубликованном `63b8abf` и новом кандидате одинаковое пересечение: 3 584 IPv4-адреса в 13 CIDR и 15 IPv6 `/48`. Эти CIDR уже присутствовали, новой Cloudflare-дельты нет. [Cloudflare поясняет](https://developers.cloudflare.com/fundamentals/concepts/cloudflare-ip-addresses/), что IP-диапазоны общие для проксируемых хостов. Это не подтверждает доступность сервисов из РФ. Для решения о сохранении/удалении проверить происхождение прежних включений и конкретные сервисы, не вычитать весь CDN по одному общему списку.

Происхождение проверено: весь объём пересечения уже находится в закреплённой v37-базе до overlay. Среди региональных категорий пересечение есть у Davoyan RU (2 304 IPv4), Grimbird RU, Digne RU, Golukon RU и Loyalsoldier RU (по 2 048 IPv4 в каждом источнике), а также Loyalsoldier BY (256 IPv4). Пересечения накладываются друг на друга и не суммируются. Это не самостоятельный импорт Cloudflare и не подтверждение доступности конкретных сервисов.
