## Происхождение /24 и доверенные входы

[Перечитаны](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/44060933231) 227 484 строки provenance с проверкой SHA-256 закреплённого ZIP, DAT и TSV. Каждый /24 имеет две полные строки — `static-override` и `rir-rukzby-selected-origin-protected`. [В проверенном исходном архиве](https://github.com/SpeedeMiner/Geoip-ru-server/actions/runs/44061405824) извлечены 97 509 ASN-файлов ipverse, оригинальный selected sidecar и оригинальные аудитные DAT Hydra, Loyalsoldier и v2fly. Хэши исходных файлов сверены с input provenance.

У всех шести selected sidecar содержит только исторический ASN с `[RIR-RU][STATIC-DIRECT]`; в исходном ipverse ни один из исторических ASN не покрывает свой /24. [Экстрактор](https://github.com/SpeedeMiner/Geoip-ru-server/blob/4b13dd5abb7a32a40a706371a8ca4616ed041a34/.github/scripts/extract_ru_asn_prefixes_v41.py#L288-L305) добавляет ручную запись **после** проверки наблюдений, а [workflow](https://github.com/SpeedeMiner/Geoip-ru-server/blob/4b13dd5abb7a32a40a706371a8ca4616ed041a34/.github/workflows/geoip-v41.yml#L223-L246) строит региональный слой из этого же selected sidecar. Поэтому две записи не означают два независимых подтверждения. Исходный CI кандидата также явно предупредил по всем шести и показал 2/8 BGP-covered overrides для полного реестра из восьми `[STATIC-DIRECT]`.

Оригинальные Hydra (все три категории) и Loyalsoldier (RU, BY, PRIVATE) не пересекают шесть /24. Все шесть целиком покрываются только иностранными категориями оригинального v2fly — пять US и один DE, из них три совпадают точным ключом. Это данные закреплённого кандидата, не утверждение о сегодняшних версиях upstream. География v2fly не устанавливает физическое размещение и не является результатом замера. **Не удалять, не добавлять в DIRECT и не импортировать US/DE по этому отчёту.**

RIPEstat Routing Status и Prefix Overview на запрос 08:00 UTC вновь вернули срез **00:00 UTC**. Именно у этого возвращённого среза 2× AS401650 (320/321 peers), 4× AS152606 (318/321) и совпадение с исходным ipverse. Свежие запросы RPKI вернули valid для этих пар, но не подтверждают время BGP-наблюдения или доступность. Эти два endpoint не подтвердили срез 08:00.

**Дальше** — проверять только новый документированный точный IP или имя с A внутри очереди. Дата `2026-12-17` остаётся датой ручного пересмотра. Код только предупреждает о наступлении `review_after` и продолжает добавлять строки; автоистечения нет. Кандидат, правила DIRECT, PR №5, release и CDN сохранены без изменений. ## Ближайшее к 08:00 наблюдение BGP State

После проверки поля времени `timestamp` endpoint BGP State вернул фактическое время **07:59:59 UTC** для всех шести точных /24 при запросе 08:00:00 UTC. У двух `156.*` все 340 возвращённых точных путей на каждый /24 оканчиваются AS401650, у четырёх `177.*` все 321 путь на каждый /24 оканчиваются AS152606. Это счётчик маршрутов этого API, не число full-feed peers из Routing Status. Указана точная секунда ответа, а не заявлен срез ровно на 08:00.
