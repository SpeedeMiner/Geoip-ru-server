## Что удерживает два префикса

В релизном selected-origin BGP списке есть отдельный `2a0b:4e07:63f1::/48`. Кандидат вместо него использует агрегированный `2a0b:4e07:63f0::/47` для того же AS218750. В обоих снимках соответствующее покрытие уже есть в базе v37. Оверлей также получает его через выбранные региональные origin ASN. Это не префикс из RIR-RU адресного инвентаря и не исключение из блокировок. Родительская делегация `2a0b:4e00::/29` в сохранённом RIPE delegated statistics имеет код IL. RDAP возвращает более специфичный родительский объект `2a0b:4e07:6300::/40` с кодом RU, но у самих дочерних /48 свои отдельные записи.

| --- | --- | --- | --- |

ROA проверяет разрешённый origin, а не страну эксплуатации. Geofeed оператора закреплён по [коммиту 551d3fb](https://github.com/egor-white/geofeed/blob/551d3fb527c36a71875319e47bba4df7709b9d33/geofeed.csv), SHA-256 `82e9ea3540a119d73cf8e5d1a0d94d1fdf323755130fbfdfdb5c2640920268b2`. ## Что меняет точечное исключение

Проведена отдельная локальная пересборка оверлея на каждой паре зафиксированных входов. Экспериментальный парсер принял только точные IPv6 /48, а список для теста содержал ровно `63f0::/48` и `63f1::/48`. Для эксперимента использована существующая механика адресного вычитания, не фильтрация строк и не исключение ASN. База v37 намеренно не пересобиралась и не изменялась. Код и строки эксперимента не вошли в PR.

| Прогон | Удаление из финального DIRECT относительно своего снимка |
| --- | --- |
| Контроль, кандидат без новых правил | 0, все бинарники совпали |
| Релиз, два правила /48 | Только `2a0b:4e07:63f1::/48`, потому что KP /48 ещё отсутствовал |
| Кандидат, два правила /48 | Ровно два проверенных /48. Дельта канонически схлопывается в `2a0b:4e07:63f0::/47` |

Для обоих пробных кандидатов нет новых адресов и нет изменений IPv4, PRIVATE или масок блокировок. Обе версии SRS декомпилированы и сверены с DAT. Прошли независимая валидация оверлея, gate hard/PRIVATE, все 14 Telegram CIDR и проверка пределов дельты. Оставшееся покрытие AS218750, в том числе московский `6301::/48`, не тронуто. Для геосигналов соседних `6300::/48` (NL), `6310::/48` (DE) и `63ff::/48` (RDAP EU, geofeed без страны) отдельного исключения не пробовали. Они записаны в очередь, а не автоматически признаны недоступными.

SHA-256 пробного релизного DAT `64aaf1ae5818ffb6c7b61c5e63221133b3058d6b8bc40ed26f56116f477952b2`. SHA-256 пробного DAT из входов CI `2895e477781ae4da211a3fe54ada3066e0d62b068af6ebf9719dc13284bcd066`.

## Решение для PR

PR №41 остаётся обновлением реестра без правки маршрутов. Не исключать AS218750 целиком и не добавлять эти /48 как строки действующей IPv4-таблицы. Её `delegated_country` означает региональную делегацию и не должен заполняться RU из страны ASN. Для будущего изменения политики предпочтителен отдельный ограниченный список IPv6 исключений с явным основанием `selected_origin_ASN`, ссылками на точные назначения и geofeed. Модель должна вычитать их из финального DIRECT, не из PRIVATE и не записывать как hard-блокировки. Эта запись не утверждает, что префиксы недоступны из RU.
